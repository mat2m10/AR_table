# AR_table

Blender (bpy) scripts that procedurally model a "sandbox" gaming table sized
for a Warhammer 40K Onslaught board (44 x 90 inches), plus a reference layout
of the standard board sizes.

The "AR" part (camera, projector, marker tracking) was never started. This
repo only contains the table geometry.

## What gets built

`sandbox_assembly.py` builds, under a `sandbox_root` empty:

| Part | Script | Size |
|------|--------|------|
| Floor slab | `sandbox_floor.py` | 111.8 x 228.6 cm, 10 cm thick, 6 x 15 grid of 4 cm holes for cables / hoses |
| Long walls (x2) | `sandbox_wall_long.py` | 244.6 x 8 x 15 cm |
| Short walls (x2) | `sandbox_wall_short.py` | 111.8 x 8 x 15 cm |
| Cross beams (x3) | `sandbox_beams.py` | 127.8 x 8 x 10 cm, under the floor at 25 / 50 / 75 % of the length |

`board_size_generation.py` lays out flat boards for Kill Team (30x22"),
Necromunda tile (12x12"), Combat Patrol (44x30"), Strike Force (44x60") and
Onslaught (44x90") side by side, with their top surface at Z = 0 (the top of
the sandbox floor). Sizes live in `scene_boards.py` (`BOARDS`).

All dimensions are module-level constants at the top of each script (metres).

## Requirements

- Blender with its bundled Python. The Blender version was not recorded; the
  scripts only use basic `bpy.ops.mesh.primitive_*`, Solidify and Boolean
  modifiers, so any recent 3.x / 4.x release should work.

## How to run

The scripts find each other through the folder of the **saved** `.blend`
file (`bpy.data.filepath`), so:

1. Start Blender and save a new `.blend` file **in this folder**
   (next to the `.py` files). `*.blend` is in `.gitignore`, so the scene
   itself is not versioned; it is fully regenerated by the scripts.
2. Open the *Scripting* workspace, open `sandbox_assembly.py` in the text
   editor and press *Run Script*. This builds the floor, walls and beams.
3. Optionally open and run `board_size_generation.py` to add the board
   size references on top.

Re-running a script deletes the objects it created before and rebuilds them,
and the modules are reloaded, so you can edit a `.py` file and run again
without restarting Blender.

If the `.blend` is unsaved, `bpy.data.filepath` is empty and the imports fail
with `ModuleNotFoundError`.
